# Phone Review Guide

## Purpose

This guide helps the instructor review the current vertical slice from a phone.

The goal is to make the draft PR easier to inspect without needing a full laptop workflow.

## Review Order

Start with these files in this order:

1. `00_MANIFEST/PROJECT_CHARTER.md`
2. `10_PRODUCT/TEACHER_DASHBOARD_MAP.md`
3. `10_PRODUCT/TEACHER_WORKFLOW_WIREFRAME.md`
4. `20_CURRICULUM/COURSE_INDEX.md`
5. `20_CURRICULUM/assignment-packs/CONDUIT_BENDING_BASIC_90_ASSIGNMENT_PACK.md`

## Five-Minute Phone Review

If you only have five minutes, answer these questions:

1. Does the charter sound like the right project?
2. Does the dashboard map feel like a usable teacher front door?
3. Do the two assignment packs feel like real classroom artifacts?
4. Does the teacher-facing AI boundary still feel clear?
5. Does the next step feel obvious?

## Quick Judgment Scale

For each file, use this simple scale:

- Keep
- Revise
- Too much
- Too thin
- Needs classroom reality
- Ready for next slice

## What to Look For

Look for whether the work feels:

- useful
- plain-language
- teacher-controlled
- realistic for Electrical Trades
- easy to test
- aligned with governance
- not overbuilt

## Best Phone Feedback Format

Use short notes like:

- Keep this phrase
- Too abstract
- Needs example
- Good for dashboard
- Not classroom-ready yet
- Make this simpler
- This feels like my classroom

## Current Review Target

The current review target is not perfection.

The target is whether the OS skeleton is strong enough to move toward an interactable Google Workspace prototype.
