# Studio 5000 / Emulate 3D Vertical Slice

## Purpose

This is a course-specific proof slice for Studio 5000 / Emulate 3D.

The goal is to show how the Electrical Trades Program OS supports automation literacy, sequencing, simulation thinking, troubleshooting, documentation, and modern industrial awareness.

## Course

Studio 5000 / Emulate 3D

## Course Role

Studio 5000 / Emulate 3D builds automation literacy, PLC logic, simulation thinking, sequencing, controls reasoning, troubleshooting, and modern industrial awareness.

## Why This Course Matters

Controls and automation help students connect electrical concepts to modern industrial systems.

This course helps the OS support:

- sequencing
- input/output thinking
- simulation literacy
- troubleshooting logic
- documentation
- calm problem response
- motor-control context
- handoff readiness

## Starter Unit

Basic I/O Identification and Sequence Explanation

## Technical Skill

Students identify basic inputs and outputs in a simple automation scenario and explain the intended sequence of operation.

## Student Task

Students will review a simple simulated automation scenario, identify inputs and outputs, describe the sequence, and explain one possible troubleshooting check.

## Materials and Tools

- Studio 5000 or Emulate 3D environment, if available
- teacher-provided screenshot or scenario
- assignment sheet
- pencil or digital workspace
- I/O list or simple reference table

## Safety Lens

Energy awareness and simulation-to-real-world verification.

Student prompt:

Even in simulation, identify what would need to be verified before working with real equipment. Name one assumption that should not be carried from simulation into the field without checking.

## Leadership Lens

Calm problem response.

Student prompt:

If the sequence does not work as expected, describe the issue clearly, avoid blame, and identify the next check.

## Executive-Function Scaffold

Sequence check.

Student prompt:

List the intended sequence in order before explaining or troubleshooting the system.

## Documentation Habit

Students record:

- input identified
- output identified
- sequence steps
- expected system behavior
- one possible fault or mismatch
- next troubleshooting check

## Rubric Criteria

| Criteria | Evidence of Success |
|---|---|
| I/O Identification | Student identifies inputs and outputs correctly. |
| Sequence Explanation | Student explains the intended sequence clearly. |
| Troubleshooting Logic | Student identifies a reasonable next check. |
| Safety Awareness | Student connects simulation to real-world verification. |
| Calm Problem Response | Student describes the issue clearly and professionally. |
| Documentation | Student records the sequence and checks clearly. |

## Reflection Prompt

What part of the sequence was easiest to misunderstand? What would you check first if the system did not respond as expected?

## Teacher Notes

Possible common errors:

- confusing inputs and outputs
- describing behavior out of sequence
- assuming simulation equals field condition
- guessing instead of checking evidence
- skipping documentation

Teacher reminders:

- sequence matters
- simulation is a learning environment, not a substitute for field verification
- troubleshooting should be calm and evidence-based
- controls work connects to motors, safety, and communication
