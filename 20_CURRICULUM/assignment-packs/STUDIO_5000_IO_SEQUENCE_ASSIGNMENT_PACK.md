# Assignment Pack: Basic I/O Identification and Sequence Explanation

## Assignment Header

| Field | Entry |
|---|---|
| Assignment Title | Basic I/O Identification and Sequence Explanation |
| Course | Studio 5000 / Emulate 3D |
| Unit or Topic | Inputs, outputs, and sequence of operation |
| Assignment Type | Controls / Automation |
| Teacher Review Status | Draft |

## Technical Skill

Students identify basic inputs and outputs in a simple automation scenario and explain the intended sequence of operation.

## Student Task

Students will:

1. Review a simple simulated automation scenario.
2. Identify at least one input.
3. Identify at least one output.
4. Describe the intended sequence in order.
5. Explain one possible troubleshooting check.
6. Connect the simulation to one real-world verification concern.

## Materials and Tools

- Studio 5000 or Emulate 3D environment, if available
- teacher-provided screenshot or scenario
- assignment sheet
- pencil or digital workspace
- I/O list or simple reference table

## Safety Lens

Energy awareness and simulation-to-real-world verification.

Even in simulation, students identify what would need to be verified before working with real equipment.

## Leadership Lens

Calm problem response.

If the sequence does not work as expected, students describe the issue clearly and identify the next check.

## Executive-Function Scaffold

Sequence check.

Students list the intended sequence in order before explaining or troubleshooting the system.

## Documentation Habit

Students record:

- input identified
- output identified
- sequence steps
- expected system behavior
- one possible fault or mismatch
- next troubleshooting check

## Rubric

| Criteria | Evidence of Success |
|---|---|
| I/O Identification | Student identifies inputs and outputs correctly. |
| Sequence Explanation | Student explains the intended sequence clearly. |
| Troubleshooting Logic | Student identifies a reasonable next check. |
| Safety Awareness | Student connects simulation to real-world verification. |
| Problem Response | Student describes the issue clearly and professionally. |
| Documentation | Student records the sequence and checks clearly. |

## Reflection Prompt

What part of the sequence was easiest to misunderstand?

What would you check first if the system did not respond as expected?

## Teacher Notes

Watch for students confusing inputs and outputs, describing behavior out of sequence, or assuming simulation equals a field condition.
